AmiDrive 0.4.1 - a OneDrive client for AmigaOS 3.x
==================================================

AmiDrive synchronises ONE chosen OneDrive folder with a drawer on the Amiga,
both ways. Files put into that folder on a phone or PC appear on the Amiga,
files changed on the Amiga go to the cloud. It talks to Microsoft directly
(HTTPS), no PC or Raspberry Pi in between.


Requirements
------------
- AmigaOS 3.0 or newer (tested on 3.2.2), a 68020 or faster, a few MB of
  Fast RAM,
- a TCP/IP stack with bsdsocket.library (Roadshow, AmiTCP, Miami), internet,
- AmiSSL 5.24 or newer (Aminet: util/libs/AmiSSL-5.x),
- a correct Amiga clock - AmiDrive can set it (option CLOCK),
- a Microsoft account with OneDrive (personal or work / school).


Installation
------------
1. Unpack the archive, e.g. to RAM:.
2. Double-click the icon "Install-AmiDrive".
3. The installer asks:
   - where to install the program (a drawer AmiDrive is created),
   - where to keep the OneDrive files (disk or drawer + name, e.g.
     Work:OneDrive),
   - which OneDrive folder to synchronise (e.g. /Amiga - it must exist,
     create it in the browser or the OneDrive app),
   - the character set of names, how often to check, both ways or download
     only, the "OneDrive" icon on the Workbench,
   - the Amiga clock (set it from the Internet / ask / do not check),
     autostart,
   - always: the time zone (TZ variable with summer time; it shows the clock
     and the current setting) and whether to set the clock from the net now.
4. At the end AmiDrive can start at once. On the first start it shows a
   code in a window: open https://login.microsoft.com/device on a phone or
   PC, enter the code, sign in and allow AmiDrive to access your files.

Installing again (a new version) stops a running AmiDrive and can keep the
current settings.


Every day
---------
AmiDrive works in the background without a window and checks for changes
every few minutes. A window appears only on an error or for signing in.

The "OneDrive" icon on the Workbench (while AmiDrive runs; while it
synchronises it shows orange round arrows instead of the blue and green ones):
  double-click        opens the drawer with the files (AmigaOS 3.5+; from
                      3.9/3.2: all files, listed by name) and the AmiDrive
                      window with buttons - at once, also during a
                      synchronisation
  files dropped on it are copied into the drawer and sent at once (during a
                      synchronisation: right after it)
  Tools menu          "AmiDrive: status", "AmiDrive: synchronise now"
                      and "AmiDrive: quit"

The drawer with the files always opens right below the AmiDrive window, as
wide, showing all files by name (AmiDrive sets this in the drawer's icon
before each opening; the icon's image and place are kept). Workbench does
not notice files changed by other programs, so after a synchronisation that
changed something on the Amiga, AmiDrive closes and opens again the open
windows of the OneDrive drawer (and its drawers): they show what is there.

The AmiDrive window (title "OneDrive" with the version) has the buttons:
  Sync now   synchronise now (disabled while one runs; also ends a pause)
  Stop       stops the synchronisation: ends a running one and pauses the
             checks ("Paused") until "Sync now"; AmiDrive keeps running
  Quit       ends AmiDrive (the OneDrive icon goes away; again: the program
             icon, or autostart the next time the Amiga starts)
The close gadget only hides the window. Workbench 3.2 has no right-button menus for
icons - the same commands are in the Tools menu as well.

During a synchronisation the window shows what is being done, a bar with
the percentage, the current file, how much is downloaded / sent, the speed
and the estimated time left. The percentage of the whole is known for the
first synchronisation (the size of the OneDrive folder) and for sending; for
ordinary changes the bar shows the current file. It opens by itself during a
long first synchronisation. Between synchronisations it shows the time and
result of the last check and when the next one is. Closing it does not stop
AmiDrive.

In a Shell:
  AmiDrive                   work in the background
  AmiDrive ONCE              one pass
  AmiDrive STOP              end the AmiDrive running in the background (as Quit)
  AmiDrive INFO              settings, sign-in, OneDrive space
  AmiDrive LOGIN / LOGOUT    sign in / delete the token
  AmiDrive TEST              clock, time zone, DNS, TLS, connection
  AmiDrive SETCLOCK          set the Amiga clock (and battery clock) from the net

Log: <drawer with the files>/.AmiDrive/AmiDrive.log


Options (Shell and Tool Types of the program icon)
--------------------------------------------------
  LOCAL=drawer           the files on the Amiga, e.g. Work:OneDrive
  REMOTE=/folder         the OneDrive folder, e.g. /Amiga
  CHARSET=LATIN1|LATIN2  character set of names
  INTERVAL=min           minutes between checks (default 3)
  UPLOAD=YES|NO          NO: download from the cloud only
  APPICON=YES|NO         the "OneDrive" icon on the Workbench
  CLOCK=ASK|AUTO|NO      wrong clock: window / set it / nothing
  STATE=drawer           another place for the state and the log
  WINDOW                 (from the icon) a window with the progress
  CLIENTID= TENANT=      your own app registration (see below)

Options given in a Shell are remembered in ENVARC:AmiDrive/AmiDrive.prefs.
Tool Types take precedence but are not saved ("(...)" = switched off).


How it works
------------
- Changes in the cloud: AmiDrive asks OneDrive only for what changed since
  the last time, downloads new files, moves and deletes what changed there.
- Changes on the Amiga: new and changed files are sent, moved ones moved,
  deleted ones deleted (into the OneDrive recycle bin).
- A file changed in both places: the cloud version gets the right name, the
  Amiga version is kept as "name-Amiga.ext" and sent as well.
- When most files are missing (e.g. a disk not mounted), nothing is deleted.
- Names longer than the disk allows (OFS/FFS: 30 characters) become
  "start~hhhhhh.ext"; protection bits and comments are not transferred.


The Amiga clock
---------------
Encrypted connections need a correct date: with a wrong clock the server
certificates look "not yet valid" or "expired" and signing in fails. AmiDrive
then takes the time from the Microsoft server (verified by its certificate;
only its dates are not checked) and:
  CLOCK=ASK   (default) shows a window with the Amiga time and the Internet
              time and the buttons "Set clock", "Always set automatically"
              (set it and from now on CLOCK=AUTO) and "Cancel",
  CLOCK=AUTO  sets the clock by itself: at the start and once a day,
  CLOCK=NO    checks nothing.
The system clock and the battery clock are set (like SetClock SAVE). Amigas
without a battery clock: CLOCK=AUTO, or "AmiDrive SETCLOCK" in S:User-Startup
after the network is started.


Several OneDrive accounts (up to 3)
-----------------------------------
In the (active) AmiDrive window the right mouse button shows the menu
"Account":
  1  Jan Kowalski (business)  (start)   the accounts; the active one is
  2  Jan Kowalski (personal)             checked, "(start)" - the start one
  3  (empty)
  Start with this account        always start with the active account
                                 (again: start with the last one used)
  Sign in...                     sign in to the active account (code shown)
  Sign out                       delete the active account's token
One account is synchronised at a time. Choosing another account switches
AmiDrive to it; the first time an empty account is chosen AmiDrive shows a
sign-in code, then asks for a drawer on the Amiga (system file requester) and
a folder in that OneDrive (it must exist). Each account has its own drawer
(two accounts cannot share one), its own folder and token. The icon on the
Workbench is called "OneDrive", "OneDrive 2" or "OneDrive 3".
Without a start account AmiDrive begins with the last one used.
In a Shell: AmiDrive ACCOUNT=2 (switches, remembered), AmiDrive ACCOUNT=2 LOGIN,
AmiDrive START=1 (always start with account 1; START=0 - the last one used).
Files: account 1 in AmiDrive.prefs and token, accounts 2 and 3 in
Account2.prefs / Account3.prefs and token2 / token3 (ENVARC:AmiDrive).


Work account of another organisation
------------------------------------
An administrator may require consent for the AmiDrive app. Then either the
administrator grants it, or the organisation registers its own app in
Microsoft Entra ID (public client, "Allow public client flows: Yes",
Microsoft Graph permissions Files.ReadWrite and offline_access) and uses:
  AmiDrive CLIENTID=<application id> TENANT=<tenant id>
  AmiDrive LOGIN


Speed
-----
The connections to OneDrive are encrypted, and on the Amiga the encryption,
not the network, sets the speed. Measured on an A1200 with a 68060/50 and the
Warp's Ethernet, the same 5 MB file: no encryption 1590 KB/s, AES-256 215 KB/s,
ChaCha20 337 KB/s. AmiDrive offers the ciphers fastest on a 68k (ChaCha20,
then AES-128); the Microsoft servers choose AES-128: a full synchronisation of
20 MB from OneDrive takes about 108 s (192 KB/s; with AES-256 it was 130 s).
Measure it yourself: AmiDrive TEST URL=https://... (and http://... to compare).


Security
--------
ENVARC:AmiDrive/token gives access to your OneDrive files - do not share
it. AmiDrive LOGOUT deletes it from the Amiga; access can also be revoked
in the Microsoft account. Server certificates are always checked.


Uninstalling
------------
AmiDrive STOP, then delete the program drawer, ENVARC:AmiDrive,
SYS:WBStartup/AmiDrive(.info) and, if wanted, the drawer with the files
(the files stay in OneDrive as well).


Reporting bugs: give the version (Version AmiDrive) and attach the log
<drawer with the files>/.AmiDrive/AmiDrive.log (it holds no tokens).
